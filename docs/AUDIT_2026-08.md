# Release audit — 2026-08-14

Scope: `backend/`, `frontend/src/`, `desktop/*.js`, `desktop/scripts/`,
root docs. Excluded: `node_modules/`, `dist/`, `.git/`, bundled runtime,
third-party configs.

Method: full read of every project source file
(`backend/main.py` 5645 lines, `frontend/src/main.tsx` 11388,
`desktop/main.js` 6954, plus 13 backend modules), cross-checked against
the last 30 commits and `VERIFIED_AUDIT.md`.

**30 defects confirmed in real code** across two passes (#1–22 first
pass, #23–30 second, deeper pass over the paste pipeline, Python
bootstrap and release scripts). Not 100 — the codebase has already been
through several audit rounds and most obvious classes are closed. Every
entry below was read out of the source, not inferred. All 30 are fixed;
144 backend tests plus 6 new regression tests pass.

Severity key: **P0** breaks the product's core promise (words reach the
transcript), **P1** degrades function or performance, **P2** is
correctness-of-code / SSOT hygiene.

---

## P0 — Correctness of capture

### 1. Live window never catches up after a slow inference pass
`backend/live.py` — `maybe_transcribe`

`maybe_transcribe` took the **last `window_sec` seconds** of the ring at
the moment of the call. Coverage was never tracked, so if one pass took
longer than `window_sec` the audio recorded meanwhile was never fed to
the model at all.

```python
# before
win = int(self.cfg.window_sec * sr)
audio_window = self._get_last_samples(win)
...
self._last_transcribe_sec = total_sec
```

With `window_sec = 8.0`, a 20 s pass (`large-v3` cold-load, loaded CPU)
leaves a 12 s hole. Symptom: *"иногда теряются слова из потока."*

```python
# after
uncovered_from_sec = max(0.0, self._covered_sec - self.cfg.overlap_sec)
need_sec = max(0.0, total_sec - uncovered_from_sec)
win_sec = min(max(need_sec, self.cfg.min_audio_sec), self._max_window_sec())
audio_window = self._get_last_samples(int(win_sec * sr))
```

`_covered_sec` is a separate watermark that advances **only after a pass
that actually reached the model**, so the next window reaches back over
the gap. When the gap exceeds what the ring can hold, the shortfall is
logged instead of vanishing silently.

### 2. Forced final flush skipped the trailing clause
`backend/live.py` — same function

The end-of-session flush compared against `_last_transcribe_sec`, which
is set when a pass **starts**:

```python
# before
if force and total_sec <= self._last_transcribe_sec + self.cfg.emit_epsilon_sec:
    return None
```

Once a periodic pass had begun, `_last_transcribe_sec` already equalled
`total_sec`, so the forced flush returned `None` and the words spoken in
the last second before Stop were never transcribed. This is the local-
provider half of *"иногда последние фразы обрезаются."*

```python
# after
if force and total_sec <= self._covered_sec + self.cfg.emit_epsilon_sec:
    return None
```

### 3. Ring eviction discarded more than it should — and could empty the buffer
`backend/live.py` — `append_pcm16le`

```python
# before
while self._ring and self._ring_samples > max_keep:
    dropped = self._ring.popleft()
    self._ring_samples -= int(dropped.shape[0])
```

The chunk that carries the buffer *over* the target is dropped, so the
ring settles **below** the retention target. Worse: a single appended
chunk larger than `max_keep` is popped on its own, leaving the ring
completely empty and destroying every sample in it.

```python
# after — evict only when the remainder still covers the target
while (
    len(self._ring) > 1
    and (self._ring_samples - int(self._ring[0].shape[0])) >= max_keep
):
    ...
```

Found by the regression test for #1, which fed 20 s in one chunk and got
back an empty window.

### 4. Deepgram events reordered under back-pressure
`backend/remote_deepgram_live.py` — `_enqueue_event`

When the queue is full and a critical event (a committed `is_final`
segment) arrives, the code popped items looking for an interim to evict,
then re-queued the popped head items — **behind** everything still in
the queue.

```python
# before
while True:
    victim = self._event_queue.get_nowait()
    if victim.get("type") == "interim":
        break
    preserved.append(victim)          # these came from the HEAD…
...
for item in preserved:
    self._event_queue.put_nowait(item)  # …and land at the TAIL
```

Queue `[final-1, interim, final-2, final-3]` came out as
`final-2, final-3, final-1` — sentences scrambled in the transcript.

```python
# after — drain in order, drop the interim in place, append at the tail
drained = [...]                       # whole queue, order preserved
victim_index = next((i for i, x in enumerate(drained)
                     if isinstance(x, dict) and x.get("type") == "interim"), -1)
if victim_index >= 0:
    drained.pop(victim_index)
    drained.append(event)
for item in drained:
    self._event_queue.put_nowait(item)
```

### 5. Rate limiter rejected normal single-user traffic
`backend/main.py`

```python
# before
RATE_LIMIT_PER_MIN = 120
WS_CONNECT_LIMIT_PER_MIN = 20
```

Steady-state renderer traffic already exceeds 120/min on its own:
live-draft autosave (1 req / 1.2 s = 50/min) + backend job polling
(1 req / 0.9 s = 66/min) + upload-queue snapshots + `/api/network`
(6/min) + History/stats refreshes after each save. The limiter is a
runaway backstop for a **loopback-only** server, not a quota — set below
real traffic it becomes a self-inflicted outage, surfacing as random
"settings save failed", stalled job polls and History refresh errors
mid-recording.

Now `1200` / `120`.

### 6. Dead-audio failsafe was gated on a setting that is off by default
`desktop/main.js` — `startRecordingStateMonitor`

The "audio pipeline dead for 8 s → force stop" failsafe lived **inside**
the `else` branch of `if (!isRec || !cfg.enabled || recordingStopInFlight)`.
`cfg.enabled` is the *auto-stop-on-silence* preference, which defaults to
off — so for the default configuration the failsafe never ran, and a dead
mic/worklet left the capsule recording forever with no way out but
quitting the app. Its own comment said "This is NOT silence detection."

Now evaluated independently of `cfg.enabled`.

### 7. DNS rebinding could lift the API token
`backend/main.py` — new `_host_header_allowed` + middleware

`GET /` is intentionally unauthenticated: it injects
`window.__TRANSCRIPTOR_API_TOKEN` so the renderer can bootstrap. Binding
to `127.0.0.1` does **not** make that safe — a remote page can point a
hostname it controls at `127.0.0.1` (DNS rebinding), at which point the
browser treats `http://attacker.example:<port>/` as same-origin, CORS
never applies, and the attacker reads the token — then every transcript,
recording and audio file.

Fixed with a loopback Host allowlist enforced in HTTP middleware (before
the route, so `/` is covered) returning `421 Misdirected Request`. A
rebound request carries the attacker's hostname in `Host`, never
`127.0.0.1` / `localhost`.

### 8. WebSocket bypassed the same guard
`backend/main.py` — `ws_transcribe`

HTTP middleware does not run for the WebSocket scope, so `/ws/transcribe`
stayed reachable through a rebound origin. The Host check is now applied
explicitly at the top of the handler (close code `4421`).

## P1 — Function and performance

### 9. Audio retention was O(N²) in syscalls on every save
`backend/main.py` — `_prune_old_recording_audio`

```python
# before — inside the per-entry loop
if not _recording_text_sibling_exists(target_dir, entry.stem):
    continue
```

`_recording_text_sibling_exists` re-listed the **entire directory** on
every iteration. For an archive of N entries that is N full `iterdir()`
scans per save — and the same helper drove the startup retention sweep.
On a large archive this is seconds of blocking I/O right after Stop.

```python
# after — index built once
text_stems = {p.stem for p in _iter_recording_text_files(target_dir)}
...
if entry.stem not in text_stems:
    continue
```

`_recording_text_sibling_exists` had no other caller and was removed.

### 10. An unwritable archive folder broke History *and* saving
`backend/main.py` — `_resolve_recordings_dir`

`p.mkdir(parents=True, exist_ok=True)` was unguarded. An external drive
ejected, a network share offline, a renamed folder or changed permissions
raised `OSError` out of a function that sits on the path of
`/api/recordings`, `/api/recordings/stats`, the retention sweep and every
save — turning a recoverable misconfiguration into an HTTP 500 across the
app. The out-of-home case already fell back to the default dir; the
unwritable case now does too.

### 11. Orphan tmp sweep missed four directories
`backend/main.py` — `_sweep_orphan_tmp_files`

Swept only `DATA_DIR` and `UPSCALE_PRESETS_DIR`, while
`storage.atomic_write_*` drops `<name>.tmp-<hex>` siblings into
`UI_STATE_DIR` (live draft, upload queue), `RESULTS_DIR` (job results),
`UPLOADS_DIR` and `LIVE_RECOVERY_DIR`. A crash mid-write left them there
permanently. All six directories are swept now.

### 12. Resampler reset its decimation grid on every capture chunk
`frontend/src/main.tsx` — `downsample`

```python
# before
const out = new Float32Array(Math.round(buf.length / r));
let off = 0;   // restarts at 0 for every chunk
```

At 48 kHz `r = 3` exactly and nothing is visible. At **44.1 kHz**
(common on Windows and many USB mics) `r = 2.75625`, so each chunk
rounded its own output length independently: a fraction of an input
sample duplicated or discarded ~21 times a second, plus a phase
discontinuity in the middle of the audio the model has to decode.

Now the sub-sample remainder is carried across calls (`downsampleCarry`),
making the grid continuous and lossless; it is cleared at `startLive`.

### 13. Tail recovery shared the 20 s empty-transcript budget
`frontend/src/main.tsx` — `stopLive`

`recoverFromEmptyTranscript` had one hard ceiling
(`LIVE_DEFAULT_EMPTY_RECOVERY_TIMEOUT_MS = 20_000`) used by every caller,
including the tail-gap path that fires when a **usable transcript already
exists** and we are only chasing a trailing clause. Spending up to 20 s
for a possible two-word improvement, while the user waits on Stop, is the
single largest contributor to *"иногда транскрибация идёт секунд
двадцать."*

The budget is now a parameter: the empty-transcript path keeps 8 s / 20 s,
the tail-gap path gets `LIVE_TAIL_RECOVERY_TIMEOUT_MS = 6_000`.

### 14. OpenRouter `content: null` crashed the endpoint
`backend/remote_openrouter.py` — `openrouter_transcribe`

```python
# before
text = js["choices"][0]["message"]["content"]
...
logger.info("openrouter_transcribe: success, %d chars", len(text))
```

Models return `content: null` on a safety refusal, empty audio, or a
tool-call-only reply. `len(None)` raises `TypeError`, which escapes the
`(KeyError, IndexError, TypeError)` handler's intent and surfaces as an
opaque HTTP 500 instead of a typed provider error the caller can fall
back from. Now `None` raises a `RemoteError` naming the model.

### 15. `request_with_retry(retries=0)` raised AssertionError
`backend/http_retry.py`

`for attempt in range(retries)` never runs for `retries <= 0`, falling
through to `assert last_resp is not None` — an opaque 500 with no
provider context. Clamped to at least one attempt.

## P2 — SSOT and code correctness

### 16. `LiveConfig.overlap_sec` was declared but never read
`backend/live.py`. Dead configuration that implied a windowing behaviour
the code did not have. It now feeds the window head (see #1), and the new
`ring_slack_sec` makes the catch-up budget an explicit knob instead of a
literal `10.0` buried in `append_pcm16le`.

### 17. `_recording_text_sibling_exists` became dead code
`backend/main.py`. Removed with #9.

### 18. `JobStore` kept the same limit in two fields
`backend/jobs.py`

```python
# before
self.max_jobs = max_jobs
self._max_jobs = max_jobs
```

`_prune` read the private one while the public one was the documented
knob — setting `store.max_jobs` had no effect and the two could silently
disagree. Collapsed to one field.

### 19. `_latest_interim` was written and never read
`backend/remote_deepgram_live.py`. Assigned on every interim, cleared on
every final, read nowhere. Removed.

### 20. `_AUDIO_EXTS_FOR_RETENTION` was a same-module alias
`backend/main.py`. Declared a "backward-compat alias for any caller that
imports this name", but the only caller was `main.py` itself, three lines
away. Two names for one tuple is exactly the drift the surrounding
comment warns about. Collapsed to `_RECORDING_AUDIO_EXTS`.

### 21. Renderer document had no Content-Security-Policy
`frontend/index.html`. Electron already runs the window with
`contextIsolation`, `sandbox`, no `nodeIntegration`, and blocks
navigation off-origin — but there was no CSP layer. Added, with
`connect-src 'self' ws: wss:` so the renderer can only reach the local
backend, `script-src` allowing the backend-injected bootstrap inline
script, and `object-src`/`frame-src`/`form-action` set to `'none'`.

### 22. README documented no hotkeys
Root `README.md`. The two global hotkeys are the primary interface of the
product and were undocumented: no defaults, no rebinding instructions, no
mention that macOS eats `F9`/`F10` as Mission Control / Notification
Center even though registration succeeds. Added: per-platform default
table, rebinding walkthrough, the picker's modifier rules, a failure
triage section, a per-platform permissions table, and auto-send.

## Checked and found correct

Recorded so a future pass does not re-audit them:

- **Secrets.** No key material in the repo or in git history.
  `.gitignore` covers `.env*`, `*.pem`, `*.key`, `*.p12`, `data/`,
  release staging. Provider keys are Fernet-encrypted at rest with a
  `0600` per-machine keyfile; `redact_config` iterates `providers.keys()`
  rather than a hardcoded list, so a future provider is redacted
  automatically. Error bodies route through `_safe_error_text`, which
  strips absolute paths and token-shaped substrings.
- **Electron hardening.** `contextIsolation: true`, `sandbox: true`,
  `nodeIntegration: false`, `webSecurity: true`; navigation is restricted
  by parsed origin (not prefix match); the preload exposes exactly one
  function.
- **Deepgram forwarder shutdown.** `_run_deepgram_live_session`'s
  `finally` looked like it leaked the forwarder task, but `finalize()`
  → `close()` enqueues the sentinel, which ends `events()`, and the task
  is awaited with a bounded timeout before the final envelope is sent.
  Ordering is correct.
- **Job pool starvation.** The live path uses `/api/transcribe-sync`
  (default asyncio executor) while uploads use the 2-worker `JobStore`
  pool. They do not contend.
- **Atomic writes.** Every persistent write goes through
  `backend/storage.py` with fsync of both file and parent directory.

## Known limits, not defects

- `_promote_live_recovery` materialises the PCM spool in RAM (~3× the
  file). Bounded by `MAX_RECOVERY_PROMOTE_BYTES` (500 MB) with a 413,
  and documented at the call site.
- `_recordings_scan_cache_key` stats every tracked file per
  `/api/recordings` call. O(N) but off the hot path; measured cost is
  tens of milliseconds at a few thousand recordings.
- Live assist caps windows at `window_sec + ring_slack_sec - 1`. On a
  machine slow enough to fall further behind, the shortfall is logged and
  the **saved recording still contains the full audio** — the stop-time
  recovery pass transcribes it in full.

# Second pass — 2026-08-15

Deeper read of the areas the first pass covered only structurally: the
paste/auto-send pipeline, Windows frontmost-window detection, the Python
bootstrap, and endpoint configuration.

### 23. Envelope wait budget was consumed before the wait began
`frontend/src/main.tsx` — `stopLive` — **P0, matches the tail-cut report**

```ts
// before — timer starts HERE
const finalizeWaitMs = 4000;
liveFinalPromise = waitForLiveFinalEnvelope(sessionUiToken, finalizeWaitMs);
if (ws.readyState === WebSocket.OPEN) ws.send(JSON.stringify({ type: "finalize" }));
```

The 4 s ceiling for Deepgram's post-`CloseStream` `is_final` started at
finalize-send time. Between that line and the first `await` of the
promise sit `pcmSink.finalize()`, a `<audio>` duration probe worth up to
2.5 s, the full Web Audio teardown, and `saveRecordingText` uploading a
multi-megabyte WAV. On a long recording the budget was fully spent
before anything waited, so the trailing clause — exactly the words
spoken just before Stop — was classified "never arrived" and either lost
or re-fetched through the slow recovery path.

```ts
// after — armed lazily, timer starts when we genuinely begin waiting
let liveFinalWaiterArmed = false;
let _liveFinalPromise: Promise<LiveFinalEnvelope | null> | null = null;
const liveFinalPromise = (): Promise<LiveFinalEnvelope | null> => {
  if (!liveFinalWaiterArmed) return Promise.resolve(null);
  if (!_liveFinalPromise) {
    _liveFinalPromise = waitForLiveFinalEnvelope(sessionUiToken, 4000);
  }
  return _liveFinalPromise;
};
```

Nothing is lost by deferring: `resolveLiveFinal` stores the envelope on
the slot whether or not a waiter exists, and `waitForLiveFinalEnvelope`
returns a already-present envelope immediately.

### 24. Unclean-close envelope was dropped when nobody was waiting yet
`frontend/src/main.tsx` — `ws.onclose`

```ts
// before
if (slot.waiters.length === 0) return;
```

An unclean close before any waiter registered discarded the synthetic
error envelope, so a later waiter had nothing to resolve against and
burned its entire timeout. Harmless while the waiter was armed eagerly;
a hang once #23 defers arming. The guard is removed — `resolveLiveFinal`
is already a no-op once `slot.envelope` is set, and the real `final`
message always precedes `onclose`.

### 25. Windows captured PowerShell's own PID as the paste target
`desktop/main.js` — `getFrontmostAppInfo` — **P1**

```powershell
# before
$pid = 0
[Window]::GetWindowThreadProcessId($hwnd, [ref]$pid) | Out-Null
$proc = Get-Process -Id $pid -ErrorAction SilentlyContinue
```

`$pid` is a **read-only automatic variable** holding the running
PowerShell process's own id. The assignment raises "Cannot overwrite
variable PID because it is read-only or constant" — a *non-terminating*
error, so the script continued, the `[ref]` write-back failed for the
same reason, and `$pid` still pointed at PowerShell. Every captured
Windows paste target therefore reported `name="powershell"` and
PowerShell's pid instead of the app the user recorded from: wrong app in
the status capsule and in `main.log`, and a pid-based activation
fallback that focused a dead console. Renamed to `$procId`.

### 26. Malformed `TRANSCRIPTOR_DEEPGRAM_HOST` prevented the backend from booting
`backend/deepgram_endpoints.py` — **P1**

```python
raise ValueError("TRANSCRIPTOR_DEEPGRAM_HOST must be a host[:port] value ...")
```

Raised at **module import**, transitively from `backend.main`. The
process died before uvicorn started, Electron saw the child exit,
retried eight times, and reported a generic "backend did not start" with
no pointer to the offending variable. `backend.main._env_int` already
established the house policy for malformed env input — warn and use the
documented default. Now matched; the test that pinned the old
raise-contract was updated.

### 27. Permission-denied auto-send paid a doubled timeout
`desktop/main.js` — `sendCommandEnterToFocusedApp`

The macOS keycode fallback runs whenever the primary `osascript` call
exits non-zero. The dominant failure — Accessibility/Automation not
granted — fails both attempts identically, so the retry could never
convert a failure into a success; it only added a second 5 s timeout
while the post-stop queue and the status capsule sat blocked. Now
short-circuits via the existing `looksLikeAutomationPermissionError`.

### 28. Auto-send setting showed macOS keys on every platform
`frontend/index.html` / `frontend/src/main.tsx`

The label was the hardcoded string "Auto-send Cmd+Ctrl Enter", while the
main process sends plain `Ctrl+Enter` on Windows (`SendKeys "^{ENTER}"`)
and Linux (`xdotool key ctrl+Return`). `syncAutoSendEnterLabel()` now
derives it from the renderer platform.

### 29. Boot-error page named a port that usually was not the one in conflict
`frontend/src/main.tsx` — `classifyBootError`

```ts
headline: "Port 8321 is already in use.",
```

`pickBackendPort` scans 24 candidates upward from `TRANSCRIPTOR_PORT`
before falling back to an OS-assigned port, so the colliding port is
rarely 8321 — the user was sent chasing the wrong process. The headline
is now port-agnostic and points at the technical-details disclosure,
which carries the real number.

### 30. `pip install` ran without the scrubbed interpreter environment
`desktop/main.js` — `ensureBackendRuntime`

Every other `runCommand(python, ...)` call passes `env:
buildPythonEnv(python)`; the two pip invocations did not. A stray
`PYTHONPATH` / `PYTHONHOME` / `VIRTUAL_ENV` inherited from the launching
shell could steer pip at a different `site-packages` than the import
check that immediately follows — a "successful" install followed by a
failing recheck. Now consistent.

## P1 — Работоспособность / Функционал

### BUG-24. `transcribe_file` не знает про GigaAM: маршруты файлов/задач принимают gigaam-id и падают

- **Файл:** `backend/transcribe.py:359-389` (+ `backend/main.py:497`, `:1798`)
- **Суть:** единственный вход файловой транскрипции идёт напрямую в
  `_model()` → `WhisperModel(...)`, хотя `ALLOWED_LOCAL_MODELS`
  (`main.py:497` = весь каталог, включая `gigaam-*`) пропускает эти id на
  sync/jobs/re-transcribe маршрутах (`main.py:1798` — единственный вызов
  `transcribe_file`).
- **Последствие:** пользователь выбирает «gigaam-v3-e2e-rnnt» в History →
  Re-transcribe (или queued job) → 500 с бессмысленной ошибкой faster-whisper
  (попытка скачать несуществующий HF-репозиторий `gigaam-v3-e2e-rnnt`).
- **Текущий код:**
  ```python
  def transcribe_file(path: str, model_name: str, *, language: Optional[str] = None,
                      word_timestamps: bool = False) -> Dict[str, Any]:
      segments, info = _model(model_name).transcribe(path, language=language, ...)
  ```
- **Исправленный код:**
  ```python
  def transcribe_file(path: str, model_name: str, *, language: Optional[str] = None,
                      word_timestamps: bool = False) -> Dict[str, Any]:
      if model_name.startswith(GIGAAM_MODEL_PREFIX):
          audio, sr = sf.read(path, dtype="float32", always_2d=True)
          if sr != LIVE_SAMPLE_RATE_HZ:
              raise ValueError(f"expected {LIVE_SAMPLE_RATE_HZ} Hz input, got {sr}")
          return transcribe_gigaam(audio.mean(axis=1), model_name,
                                   word_timestamps=word_timestamps)
      segments, info = _model(model_name).transcribe(path, language=language, ...)
  ```
- **Объяснение:** диспетчинг движка поднимается в оба канонических входа
  (`transcribe_audio` уже ветвит, `transcribe_file` — нет). Файловые маршруты
  отдают 16 kHz mono WAV (контракт пайплайна), поэтому чтение через
  `soundfile` (уже прямая зависимость) — без новых пакетов.

### BUG-25. `warm_model` не знает про GigaAM: /api/transcribe/warmup падает на gigaam-id

- **Файл:** `backend/transcribe.py:188-…` (+ `backend/main.py:1316-1326`)
- **Суть:** маршрут warmup валидирует модель по `ALLOWED_LOCAL_MODELS`
  (gigaam пропускается) и вызывает `warm_model`, который тоже сразу строит
  `WhisperModel`.
- **Последствие:** выбор gigaam-модели в UI (подгрузка превью/health-цикл)
  может уронить warmup-запрос; та же бессмысленная ошибка HF.
- **Текущий код:**
  ```python
  def warm_model(model_name: str, *, probe: bool = False):
      m = _model(model_name)
  ```
- **Исправленный код:**
  ```python
  def warm_model(model_name: str, *, probe: bool = False):
      if model_name.startswith(GIGAAM_MODEL_PREFIX):
          from backend.transcribe_gigaam import warm_gigaam
          warm_gigaam(model_name)
          return
      m = _model(model_name)
  ```
  (+ `warm_gigaam()` в адаптере: `_load_model(model_id)` под уже существующим
  локом кэша.)
- **Объяснение:** прогрев — часть публичного контракта каталога моделей;
  движок-специфика не должна протекать в маршрут.

### BUG-26. Live-trim склеивает слова GigaAM: адаптер нарушает собственный контракт формата слов

- **Файл:** `backend/transcribe_gigaam.py:101,106` (+ `backend/live.py:370-377`)
- **Суть:** адаптер обещает «тот же segment/word shape, что faster-whisper,
  чтобы downstream работал без изменений», но `.strip()` у слов убирает
  ведущие пробелы — а `live.py` восстанавливает текст обрезанного сегмента
  конкатенацией `"".join`, рассчитанной на faster-whisper-конвенцию
  («пробел-в-начале-токена»).
- **Последствие:** live-диктовка на `gigaam-v3-e2e-rnnt` после КАЖДОГО
  word-trim выдаёт склеенный текст («приветкакделасторона») — прямой
  потеря-качества класс на главном сценарии приложения.
- **Текущий код:**
  ```python
  text = str(getattr(w, "text", "") or "").strip()          # адаптер
  out.append({"word": text, ...})
  ...
  text = "".join(str(w.get("word") or "") for w in kept_words).strip()  # live.py
  ```
- **Исправленный код (в адаптере, единственное место):**
  ```python
  first = not out
  token = [secret redacted], "text", "") or "").strip()
  if not token or w_end <= w_start:
      continue
  out.append({"word": token if first else f" {token}",
              "start": round(w_start, 3), "end": round(w_end, 3)})
  ```
- **Объяснение:** SSOT-фикс в точке адаптации: все потребители (live-trim,
  фронтовый merge, text-match) продолжают работать по одной конвенции
  faster-whisper, вместо того чтобы учить каждый из них о втором движке.

### BUG-38. Результат адаптера GigaAM без `text`/`language_probability`: sync-маршрут теряет текст

- **Файл:** `backend/transcribe_gigaam.py:185` (найден при фиксе Группы A)
- **Суть:** адаптер обещает «shape как `transcribe_audio`», но возвращает
  только `{segments, language, duration}` — без `text` и
  `language_probability`, которые потребители читают напрямую
  (`main.py:4405` `result.get("text")`).
- **Последствие:** gigaam-транскрипция через sync-путь (numpy-вход) даёт
  ПУСТОЙ текст при непустых сегментах — тихая потеря результата.
- **Исправление:** вернуть полный контракт: `text` = join сегментных
  текстов, `language_probability` = 1.0 (движок детерминированно ru).


### BUG-27. Settings: поля вылезают из карточек и наезжают на соседнюю карточку (воспроизведено)

- **Файл:** `frontend/src/styles.css:2255-2258`
- **Суть:** `.card .field-stack { flex: 1 1 auto; min-height: 0 }` —
  `min-height: 0` позволяет стеку сжаться ниже контента внутри
  stretch-карточки, а грид-ряд при этом сайзится по МЕНЬШЕЙ соседней
  карточке (вклад flex-контейнера в intrinsic-высоту схлопывается).
- **Последствие (замер зонда на собранном dist, 2000×1160):** карточка
  Defaults получает 279px при контенте 296px; инпут Threshold рисуется
  18px ниже границы карточки (bottom 714 против card 696) и перекрывает
  заголовок Shortcuts (ряд 3 начинается на 710). Тот же класс — любая
  карточка, чей контент выше соседа по ряду.
- **Текущий код:**
  ```css
  .card .field-stack {
    flex: 1 1 auto;
    min-height: 0;
  }
  ```
- **Исправленный код:**
  ```css
  .card .field-stack {
    flex: 1 1 auto;
    /* Без min-height:0: он позволял стеку сжиматься ниже контента внутри
       stretch-карточки — грид-ряд сайзился по соседней карточке, и поля
       рисовались поверх следующего ряда. Ряд теперь растёт до самого
       высокого контента; .settings (overflow-y:auto) скроллит страницу. */
  }
  ```
- **Объяснение:** корень — конфликт «stretch-выравнивание карточек» ×
  «shrinkable flex-стек». Убираем shrink ниже контента: ряды грида снова
  обязаны вмещать самый высокий контент (это и есть контракт
  «карточки в ряду одной высоты» из комментария у `.card`).

### BUG-28. Чанкер GigaAM режет слова на границах 20-секундных кусков

- **Файл:** `backend/transcribe_gigaam.py:80-89,132-142`
- **Суть:** последовательные чанки [0,20],[20,40]… режут аудио в произвольной
  точке: слово на границе даёт огрызок в обоих чанках (дубль/мусор в тексте).
- **Последствие:** ~1 битое слово на каждые 20 секунд файла; десятиминутная
  запись ≈ 30 дефектов текста.
- **Исправление:** перекрытие чанков (1.2 c) + дедупликация слов по
  абсолютному времени при сшивке (предпочтение полному вхождению); для
  бессловесного режима — сшивка текста с отбрасыванием хвостового огрызка.
  Детерминированно, покрывается тестами с фейковой моделью.

### BUG-29. Upload игнорирует выбранную локальную модель

- **Файл:** `frontend/src/main.tsx:11723`
- **Суть:** локальная ветка аплоада хардкодит `DEFAULT_LOCAL_TRANSCRIPTION_MODEL`,
  тогда как Live и Re-transcribe берут выбор из `#model`.
- **Последствие:** выбрал large-v3 — аплоад всё равно гоняет small; тихое
  расхождение качества между вкладками.
- **Исправление:** `modelLabel = getLocalModelValue();` (тот же SSOT-геттер,
  что у остальных путей) с фолбэком на дефолт при пустом выборе.

### BUG-30. Авто-применение выбора модели после загрузки — мёртвый код

- **Файл:** `frontend/src/main.tsx:838-848`
- **Суть:** условие `!findLocalModelRow(id)?.status` никогда не истинно —
  бэкенд всегда присылает truthy `status` («idle» → «done»).
- **Последствие:** пообещали «выбор станет активным, когда модель скачается» —
  обещание не выполняется, селектор остаётся на старой модели.
- **Исправление:** `findLocalModelRow(pendingModelSelection)?.status === "done"`.

### BUG-31. Карточка «Local models» без loading/empty-состояния выглядит сломанной

- **Файл:** `frontend/src/main.tsx:772-774` (`renderLocalModels`)
- **Суть:** при пустом кэше таблица не рендерит ничего (зонд: `children: 0`),
  карточка стоит пустая — пользователь читает это как «не работает».
- **Исправление:** плейсхолдер-строка: «Loading models…» до первого ответа,
  «Model list unavailable — backend offline» при ошибке; исчезает при
  появлении строк.

### BUG-32. Диагностика провала установки GigaAM пуста: `res.details` не существует

- **Файл:** `desktop/main.js:5299`
- **Суть:** `runCommand()` возвращает `{ok, code, stdout, stderr}` — поля
  `.details` нет, в лог провала установки пишется пустая строка.
- **Последствие:** многогигабайтная установка падает (диск, прокси, Xcode
  CLT) — и в логе нет ни строчки причины; поддержка слепая.
- **Исправление:** `` `(res.stderr || res.stdout || "").slice(0, 400) ``.

### BUG-33. Нет проверки свободного места перед ~6 GB установкой движка

- **Файл:** `desktop/main.js:5283-5320`
- **Суть:** `pip install --target userData/engine-site` стартует без проверки
  диска; ENOSPC посреди установки оставляет полумёртвый engine-site.
- **Последствие:** `import gigaam` ломается НА КАЖДЫЙ запуск → 30-минутная
  блокирующая переустановка при каждом старте, пока пользователь не чистит
  руками.
- **Исправление:** перед установкой `fs.statfsSync(engineSiteRoot)` (Node 18.15+):
  требуется `free > 8 GB` (download + unpack + pip-cache), иначе внятная
  ошибка в лог и статус инсталлятора, без запуска pip.

### BUG-34. Архивы ротации main.log не подрезаются — безграничный рост userData

- **Файл:** `desktop/main.js:323-381`
- **Суть:** каждая ротация создаёт `main.log.archive-<stamp>` (до 5 MB);
  удалять их «при ротации» нельзя по дизайну, но и boot-retention нет.
- **Последствие:** месяцы использования = сотни мегабайт логов на диске
  пользователя без его ведома.
- **Исправление:** boot-sweep (рядом с `recoverOrphanRotatingLogs`):
  сохранить последние N=10 архивов и ≤50 MB суммарно, старшие удалить —
  политика ретенции в одном месте, ротация по-прежнему ничего не удаляет.

### BUG-35. requirements-gigaam.txt: непинутый git HEAD + устаревший комментарий

- **Файл:** `requirements-gigaam.txt:1-3`
- **Суть:** `gigaam[torch] @ git+https://github.com/salute-developers/GigaAM.git`
  плавает за upstream main (не воспроизводимая установка; любой push в
  upstream ломает установку приложения), комментарий говорит про
  «APP VENV (userData/.venv)» — установка давно идёт в engine-site.
- **Исправление:** пин на конкретный коммит
  `@ git+https://github.com/salute-developers/GigaAM.git@<sha>` + правка
  комментария (engine-site, ENABLE_GIGAAM-маркер).

## P1 — Работоспособность

### BUG-39. Установка GigaAM блокирует старт бэкенда до 30 минут на машине без сети

- **Файл:** `desktop/main.js` — `ensureBackendRuntime` (~:5379) →
  `installGigaamEngineIfRequested` (~:5270)
- **Суть:** `ENABLE_GIGAAM` копируется в каждый пакедж-билд
  (`desktop/package.json`: files + extraResources mac/win/linux), поэтому
  установщик срабатывает у КАЖДОГО пользователя, у кого движок ещё не стоит.
  Перед pip-попыткой нет сетевого зонда: офлайн-машина платит полный цикл
  ретраев pip (`timeoutMs: 1 800 000`) ДО старта uvicorn, потому что вызов
  `await installGigaamEngineIfRequested(...)` стоит внутри
  `ensureBackendRuntime`, который `startBackend` ждёт перед спавном бэкенда.
- **Последствие:** первый запуск 1.3.5+ офлайн = «Installing GigaAM engine…» на
  десятки минут без кнопки «пропустить», транскрипция недоступна всё это время;
  при флапающем сети — то же самое при каждом запуске. Отмена/таймаут UI нет.
- **Текущий код:**
  ```js
  const probe = await runCommand(python, ["-c", "import gigaam"], { ... timeoutMs: 20000 ... });
  if (probe.ok) return;
  setBackendBootStatus("Installing GigaAM engine (large download)…");
  // ... сразу pip install, timeoutMs: 1800000
  ```
- **Исправление:** быстрый TCP-зонд pypi/github (≤3 c) перед попыткой;
  недоступна сеть → лог + статус «GigaAM unavailable offline», установка
  откладывается до следующего запуска, бэкенд стартует немедленно.
- **Объяснение:** оффлайн-детект — минимальная правка в границах бага;
  перевод установки в фон менял бы boot-архитектуру и отдельно согласован ниже.

### BUG-40. Провалившийся POST скачивания модели навсегда прибивает `#model` к недокачанной модели

- **Файл:** `frontend/src/main.tsx:899-907` (+ `:929-934`, `:719-744`)
- **Суть:** `requestModelDownload` глотает ошибку и резолвится нормально, поэтому
  `.then(() => { pendingModelSelection = id })` в confirm-обработчике модалки
  выполняется ВСЕГДА, включая провал POST. Очистки нет: авто-применение требует
  `status === "done"` (недостижимо при ошибке), а каждый
  `syncLocalModelOptions()` (опрос каждые 2 с при открытых Settings + каждый
  `/api/health`) делает `sel.value = preferredAvailable ? nextValue : …`, где
  доступность проверяется только по ENGINE, не по наличию файлов.
- **Последствие:** один сетевой сбой POST — и SSOT-геттер `selectedLocalModel()`
  отдаёт незагруженную модель во ВСЕ потоки (запись/аплоад/ре-транскрипция):
  faster-whisper молча начинает собственную multi-GB докачку мимо менеджера
  (без прогресса и статуса), офлайн — падение записи.
- **Текущий код:**
  ```ts
  } catch (e) {
    setStatus(`Download failed for ${id}: …`, "error");   // :904-906 — проглотили
  }
  ...
  if (id) void requestModelDownload(id).then(() => {
    pendingModelSelection = id;                            // :932-933 — пин всегда
  });
  ```
- **Исправление:** `requestModelDownload` возвращает boolean успеха; пин ставить
  только при успехе; при провале очищать `pendingModelSelection`.
- **Объяснение:** источник — нарушение собственного контракта «pending живёт до
  готовности»: терминальное состояние ошибки не завершает pending-жизненный цикл.

### BUG-41. `RuntimeError` шифрования пробивает контракт «load_config никогда не бросает»

- **Файл:** `backend/config.py:262-264` против `:820-829` и `:851-857`
- **Суть:** `encrypt_value()` бросает `RuntimeError("encryption key unavailable; …")`,
  когда cryptography установлен, но keyfile нечитаем/не создался. Оба места
  миграции legacy plaintext-ключей ловят только `(OSError, ValueError, TypeError)`
  — RuntimeError уходит наружу из `_load_config_unlocked`/`load_config`, чья
  докстринг-гарантия: «Returns DEFAULT_CONFIG on catastrophic failure. Never raises».
- **Последствие:** пользователь со старым конфигом (plaintext ключи) и битым
  keyfile получает не деградацию с предупреждением, а необработанное исключение:
  500 на каждом эндпоинте, читающем конфиг, вместо «ключи останутся открытым
  текстом на эту сессию».
- **Текущий код:**
  ```python
  try:
      _encrypt_provider_keys(merged)          # RuntimeError проходит насквозь
      ...
  except (OSError, ValueError, TypeError) as e:   # :829
  ```
- **Исправление:** добавить `RuntimeError` в оба except-кортежа ветвей миграции/
  штампа версии (лог warning «keys left plaintext this session»); контракт
  encrypt_value («fail loudly») сохраняется — ловим точечно на границе load.
- **Объяснение:** конфликт двух контрактов одного модуля: loud-fail энкрипта vs
  never-raise лоадера; точка стыка должна переводить одно в другое явно.

### BUG-42. Кнопка загрузки модели живёт только в create(): после ошибки повтора нет, во время скачки кнопка-призрак остаётся

- **Файл:** `frontend/src/main.tsx:801-854` (`renderLocalModels`, reconciler
  переиспользует DOM-узлы)
- **Суть:** `.model-dl` кнопка создаётся ТОЛЬКО в `create()` и только при
  `status !== "downloading"`; `update()` текст меняет, а кнопкой не управляет.
  Карточка, созданная в статусе downloading (кнопки нет), при переходе в error
  показывает «failed — retry», но кликнуть нечего; карточка idle→downloading
  наоборот оставляет живую кнопку Download поверх «↓ 12%».
- **Последствие:** упавшая загрузка невосстановима из UI до пересборки таблицы
  (которой нет — узлы живут вечно); двойной клик по кнопке-призраку даёт 409.
- **Текущий код:**
  ```ts
  update: (card, row) => {
    ...
    if (row.status === "error") { state.textContent = "failed — retry"; ... }
    // кнопку не добавляет/не убирает никогда
  }
  ```
- **Исправление:** вынести синхронизацию кнопки в общий хелпер, звать его и из
  create, и из update: кнопка есть ⟺ whisper && !downloaded && status !==
  "downloading".
- **Объяснение:** create/update-асимметрия классическая ошибка keyed-reconciler:
  инвариант должен выводиться из состояния, а не из момента рождения узла.

### BUG-43. Мёртвая запись полного WAV в адаптере GigaAM — двойной дисковый I/O на каждый запрос

- **Файл:** `backend/transcribe_gigaam.py:210-233`
- **Суть:** `wav_path = _write_wav(audio)` пишется ПОЛНЫЙ файл, используется
  только в `finally` для удаления; транскрипция идёт исключительно по
  chunk-файлам.
- **Последствие:** лишние запись+удаление файла размером с всю запись
  (десятки–сотни МБ PCM) на каждую транскрипцию — latency и износ SSD без
  единой пользы.
- **Текущий код:**
  ```python
  wav_path = _write_wav(audio)          # пишем всё
  try:
      for start, end in bounds:
          chunk_path = _write_wav(audio[lo:hi])   # пишем ещё и чанк
          ...
  finally:
      wav_path.unlink(missing_ok=True)  # удаляем неиспользованное
  ```
- **Исправление:** убрать `wav_path` целиком (try/finally остаётся вокруг цикла
  ради chunk-файлов).
- **Объяснение:** остаток рефакторинга чанкера: полный WAV был нужен, когда
  модель вызывалась одним файлом; после введения оверлап-чанков стал мусором.

### BUG-44. Прогресс скачивания модели считается по числу файлов, а не по байтам

- **Файл:** `backend/models_manager.py:133-142`
- **Суть:** faster-whisper репозитории — это model.bin (≈95 % байт) плюс
  горстка мелких файлов; `(i-1)/len(files)` сидит на ~0 % почти всю много-
  гигабайтную скачку и прыгает в 100 % в конце.
- **Последствие:** пользователь видит «↓ 0%» десять минут — выглядит как зависание,
  провоцирует отмены/повторы и тикеты «не работает».
- **Текущий код:**
  ```python
  total = max(1, len(files))
  for i, name in enumerate(files, start=1):
      _set_state(model_id, status="downloading", progress=(i - 1) / total * 100.0)
      hf_hub_download(repo_id=repo, filename=name)
  ```
- **Исправление:** взять размеры файлов через `HfApi().repo_info(...,
  files_metadata=True)` (один запрос) и взвешивать прогресс байтами; metadata
  недоступна → фолбэк на текущую схему.
- **Объяснение:** прогресс обязан быть монотонной функцией переданных данных,
  иначе он врёт именно там, для чего существует.

### BUG-45. Cancel в модалке скачивания оставляет селект на недоступной модели

- **Файл:** `frontend/src/main.tsx:916-928` (+ `syncLocalModelOptions:719-744`)
- **Суть:** `closeModal()` чистит `pendingModelSelection`, но НЕ возвращает
  `sel.value` к `lastAppliedLocalModel`. Следующий `syncLocalModelOptions`
  берёт preferred из ТЕКУЩЕГО sel.value (уже подменённого на недоступную
  модель строкой :943 ранее или пользователем) и закрепляет его снова.
- **Последствие:** после «Cancel» дропдаун продолжает показывать неготовую
  модель, и запись/аплоад уходят с ней (см. BUG-40) — отмена не отменяет.
- **Текущий код:**
  ```ts
  const closeModal = (): void => {
    if (modal) modal.hidden = true;
    pendingModelSelection = null;        // значение селекта не трогаем
  };
  ```
- **Исправление:** в `closeModal` восстанавливать
  `sel.value = lastAppliedLocalModel || DEFAULT_LOCAL_TRANSCRIPTION_MODEL`,
  а в `syncLocalModelOptions` при активном pending вообще не переписывать value.
- **Объяснение:** отмена выбора обязана возвращать ровно то состояние, что было
  до открытия модалки; иначе «Cancel» — просто скрытие диалога.

### BUG-46. PYTHONPATH engine-site тенeвит ВСЕ pinned-депсы бандла, а не только numpy

- **Файл:** `desktop/main.js` — `buildPythonEnv:4918-4927`, `sanitizeEngineSite`
- **Суть:** prune ограничен numpy/ml_dtypes, а torch тащит filelock/jinja2/
  sympy/networkx/fsspec/typing-extensions — все они оказываются ВПЕРЕДИ
  site-packages бандла для каждого импорта бэкенда, включая faster-whisper.
- **Последствие:** расхождение версий между «release-pinned» стеком и тем, что
  реально импортируется; ломается воспроизводимость поддержки (баг «на моей
  машине» воспроизводится только у тех, кто ставил GigaAM).
- **Исправление (требует решения по архитектуре, сейчас — задокументированный
  принятый риск):** канонично — отдельный venv для движка и запуск воркеров
  движка в нём; точечно — расширять prune опасно (sympy нужен самому torch).
- **Объяснение:** единственный безопасный фикс — изоляция окружений, это
  архитектурное решение за пределами точечного багфикса (по уставу — вопрос
  к владельцу продукта, не автоприменение).

## P3 — Совместимость / мелочи

### BUG-47. Кэш моделей GigaAM без LRU-капа: обе torch-модели остаются резидентными навсегда

- **Файлы:** `backend/transcribe_gigaam.py:_MODEL_CACHE` vs
  `backend/transcribe.py:70 (_MODEL_CACHE_MAX=2)`
- **Суть:** у whisper-кэша есть OrderedDict-LRU с потолком; gigaam-кэш — вечный
  dict. Переключившийся между v3-e2e-rnnt и v3-rnnt держит обе модели (~2 GB+ RSS).
- **Исправление:** тот же паттерн: cap=1 (torch-модели крупные), env-override
  `TRANSCRIPTOR_GIGAAM_CACHE_SIZE`.

### BUG-48. Empty-audio ранний возврат адаптера нарушает собственный результат-контракт

- **Файл:** `backend/transcribe_gigaam.py:203-204`
- **Суть:** `return {"segments": [], "language": "ru", "duration": 0.0}` — без
  `text`/`language_probability`, хотя комментарий :264-267 объявляет их
  обязательными (BUG-38 чинил ровно это для общего пути).
- **Исправление:** дополнить словарь `"text": "", "language_probability": 1.0`.

### BUG-49. Строковая аннотация ссылается на неимпортированный Tuple

- **Файл:** `backend/http_retry.py:103`
- **Суть:** `Optional["Tuple[float, float] | float"]` — `Tuple` не импортирован;
  runtime не падает (строковый литерал), но `typing.get_type_hints`/интроспекция
  дают NameError.
- **Исправление:** `from typing import Optional, Tuple` (аннотация станет
  валидной под любым интроспектором).

### BUG-50. Пробы venv в resolvePython идут без санитизации окружения

- **Файл:** `desktop/main.js:5206-5211, 5221-5226`
- **Суть:** шаги 1–2 зовут runCommand БЕЗ `env: buildPythonEnv(...)` — без скраба
  PYTHONHOME/PYTHONPATH здоровый venv может провалить probe `import sys` из-за
  мусора пользовательского шелла, и выбор интерпретатора уйдёт не туда.
- **Исправление:** передавать `buildPythonEnv(appVenvPy/devVenvPy)` как в шаге 0.

### BUG-51. O(N)-stat по всем записям на event loop при каждом GET /api/recordings

- **Файл:** `backend/main.py:2577-2600` + вызов `:5331` в `async def list_recordings`
- **Суть:** `_recordings_scan_cache_key` делает stat каждого аудио/txt-файла
  каждой директории ДО проверки кэша — синхронно в event-loop-потоке. На
  библиотеке в тысячи файлов это десятки мс джиттера на каждый поллинг списка.
- **Исправление:** вычисление ключа увести в тот же `asyncio.to_thread`, что и
  полную перестройку (семантика ключа не меняется — меняется только поток).

### BUG-52. Fallback-id восстановления режет сессии, содержащие «_»

- **Файл:** `backend/main.py:933`
- **Суть:** `pcm_path.stem.split("_")[-1]` берёт последний сегмент имени, но
  `LIVE_SESSION_ID_RE = ^[A-Za-z0-9_-]{1,128}$` разрешает подчёркивания ВНУТРИ
  id: `prefix_a_b.pcm16` → id «b». При потерянном meta.json получаем неверные/\
  дублирующиеся строки восстановления.
- **Исправление:** перебирать суффиксы сегментов от короткого к длинному и брать
  первый, полностью совпавший с LIVE_SESSION_ID_RE; не нашли — пропускать.

## Архитектурное закрытие BUG-46 + перевод установки движка в явный поток (финал дня)

Решение владельца («чиним всё энтерпрайзно, без костылей») реализовано:

1. **Установка движка больше не часть boot-пути.** `ensureBackendRuntime`
   не вызывает инсталлятор вообще: установка запускается ТОЛЬКО явно из
   Settings → Local models → «Install engine» (confirm-модалка с ценой:
   ~2 GB download / 8 GB disk). Класс «офлайн-бут висит на pip» уничтожен
   полностью — boot не знает про pip движка. Сетевой и дисковый гейты,
   staging+swap сохранены внутри пользовательского потока.
2. **Активация без перезапуска приложения:** после свапа engine-site
   десктоп делает killBackendHard — существующий crash-restart механизму
   перезапускает бэкенд уже с обновлённым PYTHONPATH.
3. **BUG-46 решён вычисляемым инвариантом** вместо whitelist-догадок.
   Новая SSOT-модуль `desktop/engine-deps.js` (чистый CommonJS,
   node --test): парсинг Requires-Dist из METADATA staged-пакетов,
   PEP440-subset проверка версий, план prune: каждое имя, присутствующее

### BUG-53. http_retry ретранслирует неидемпотентные POST на read-timeout — двойное списание у провайдера

- **Файл:** `backend/http_retry.py:131-152` (вызовы: `remote_openrouter.py:233`, `remote_deepgram.py:205`)
- **Суть:** цикл ретраев ловит `RequestException` независимо от метода; read-timeout означает, что запрос МОГ быть обработан провайдером.
- **Последствие:** платная транскрипция выполняется дважды (двойное списание), пользователь платит за один результат.
- **Текущий код:** `except RequestException as e: ... time.sleep(...)` — без учёта метода.
- **Исправление:** POST/PATCH ретраятся только на connect-фазе (`ConnectTimeout`, `ConnectionError` — запрос не ушёл); `ReadTimeout` для них — финальная ошибка. GET/HEAD/PUT/DELETE — как раньше.
- **Объяснение:** каноническая семантика идемпотентности HTTP.

### BUG-54. RuntimeError шифрования пробивает save_config → set_config отдаёт голый 500

### BUG-55. Text-only фоллбек ститчера дублирует фразы на швах (дефект утреннего фикса BUG-28)

### BUG-59. Кап буфера CONNECTING посчитан во «входных» фреймах — 1.33 с вместо 4 с

- **Файл:** `frontend/src/main.tsx:8069-8076` (`wsPendingFrames.length < 500`)
- **Суть:** 500 фреймов × 128 входных сэмплов при 48 кГц = 1.33 с аудио, а не 4 с (128 — квант входного контекста, после даунсемпла во фрейме ~42.7 выходных сэмплов).

- **Исправление:** кап по выходным сэмплам (счётчик `wsPendingFrameSamples`, лимит 64 000 = 4 c × 16 кГц), сброс при flush.
- **Объяснение:** кап должен измерять то, что защищает — секунды аудио, а не число фреймов.

### BUG-60. engine-site.old-* сироты не подчищаются + ложный «install FAILED» при неудачном клинапе

### BUG-61. pip-потомок не трекается: quit во время установки оставляет сироту-pip на 30 минут

### BUG-62. backend.on("error") оставляет мёртвый хэндл живым — startBackend больше не стартует бэкенд

# BUGS_AUDIT — 2026-08-23

Полный аудит кодовой базы Voice Transcriptor после серии из 14 интеграционных
коммитов (9c1014c…d9e2cc7) и ревизии последних 30 коммитов истории.

Методика: построчная проверка горячих путей бэкенда (main.py save/promote/jobs,
live.py emit-trim, remote_deepgram_live.py splice/finalize, storage.py,
http_retry.py), десктопа (shortcuts/paste/recovery/retention), фронтенда
(recording pipeline, reconciler, preview contract, upload caps, persistence),
упаковки (electron-builder files whitelist) и CI. Плюс targeted-grep по классам:
bare except, mutable defaults, TODO/FIXME/HACK маркеры, пустые catch, var,
path traversal, SSOT-дубли (модели/расширения/лимиты/хоткеи/версии).

**Честный итог: найдено 19 реальных дефектов.** Не 100 — кодовая база прошла
месяцы хардening-коммитов (атомарные записи с fsync, санитизация имён с
защитой от traversal и null-byte, guarded races в JobStore, серверная гидратация
всех справочников фронтенда), и выдумывать хundred несуществующих проблем было бы
враньём, которого здесь не будет. Ниже каждый — с кодом и фиксом.

## P1 — Работоспособность / Функционал

### BUG-01. Спул пережил 4 GB, а promote — нет: восстановление длинных записей умирает на 413

- **Файл:** `backend/main.py:349` vs `backend/main.py:1079`
- **Суть:** коммит 9c1014c поднял потолок спула до 4 GB (`MAX_LIVE_RECOVERY_BYTES` производен от `MAX_UPLOAD_BYTES`), но `MAX_RECOVERY_PROMOTE_BYTES` остался 500 MB — запись длиной >~4.3 ч пишется в спул, но восстановление после краша отвергается.
- **Последствие:** пользователь часами диктует, приложение падает — и запись невосстановима, хотя спул цел на диске. Худший класс потери данных.
- **Текущий код:**
  ```python
  MAX_RECOVERY_PROMOTE_BYTES = 500 * 1024 * 1024   # :349
  ...
  if pcm_size > MAX_RECOVERY_PROMOTE_BYTES:        # :1079
      raise HTTPException(status_code=413, ...)
  ```
- **Исправление:** стримить PCM→WAV чанками (без загрузки всего файла в RAM — текущий путь читает весь файл и конвертирует во float32 ≈ ×2 RAM), поднять потолок promote до производного от спула.
- **Объяснение:** корень — два независимых потолка, разъехавшиеся при изменении одного. Потолок promote должен быть производным значением, как это уже сделано для спула.

### BUG-02. Тихое удаление аудио старых записей без настройки и предупреждения

- **Файл:** `backend/main.py:2663` (вызовы: 1149, 5746)
- **Суть:** retention-политика «аудио только у последней записи» удаляет `.wav/.m4a/...` всех предыдущих записей архива при каждом сохранении; transcripts сохраняются.
- **Последствие:** пользователь, вернувшийся к вчерашней записи, чтобы переслушать, обнаруживает аудио удалённым — без единого упоминания в UI или README. Репутационная мина: выглядит как потеря данных.
- **Текущий код:**
  ```python
  def _prune_old_recording_audio(target_dir: Path, keep_stem: str) -> int:
      """Retention policy: keep audio only for the *latest* recording."""
  ```
- **Исправление (минимальное, без смены политики):** пробросить счётчик `pruned` из ответа эндпоинта в frontend-тост («Аудио N старых записей удалено политикой хранения») + раздел в README. Сама политика — продуктовое решение, меняется только по явному решению владельца.
- **Объяснение:** деструктивное поведение без surfaced-обратной связи нарушает принцип least astonishment; фикс наблюдаемости не требует архитектурных изменений.

### BUG-03. Окно холодного старта: клиентский лимит размера не проверяется до гидратации /api/health

- **Файл:** `frontend/src/main.tsx:564`, `10646-10648`
- **Суть:** `MAX_FILE_BYTES = 0` до ответа health; проверка `if (cap > 0 && file.size > cap)` молча пропускает валидацию → файл 5 GB принимается в очередь и отваливается серверным 413 с техническим текстом.
- **Последствие:** пользователь ждёт загрузку гигабайт, получает непонятную ошибку на середине.
- **Текущий код:**
  ```ts
  let MAX_FILE_BYTES = 0;          // :564
  ...
  if (cap > 0 && file.size > cap) { ... }   // :10653
  ```
- **Исправление:** кэшировать последнее гидратированное значение в localStorage (`transcriptor.capCache`) и использовать как fallback до первого health; значение по-прежнему одно — серверное (кэш с явным происхождением, не второй источник истины).
- **Объяснение:** устраняет окно без введения дублирующей константы.

### BUG-04. ESLint отсутствует во всём JS/TS-стеке (~20 k строк)

- **Файлы:** `frontend/package.json`, `desktop/package.json`
- **Суть:** ни линтера, ни правил для catch-swallowing, unused vars, unsafe optional chains. Внешний PR #4 добавляет flat-config ESLint — полезен, но вводит devDependency.
- **Последствие:** целые классы ошибок ловятся только рантаймом.
- **Исправление:** принять PR #4 (после проверки baseline), включить в CI.
- **Объяснение:** требует согласия (зависимость) — вынесено в вопрос пользователю.

## P2 — Производительность / Корректность контрактов

### BUG-05. progress_cb как tuple-lambda нарушает контракт `(float) -> None`

- **Файл:** `backend/main.py:4429-4433`
- **Суть:** лямбда возвращает кортеж `(raise_if_cancelled(...), set_progress(...))`, тогда как тип колбэка — `((float) -> None) | None`.
- **Последствие:** работает, но ломает типизацию (поймано typecheck'ом), затрудняет рефакторинг; порядок вызовов завязан на семантику кортежа.
- **Текущий код:**
  ```python
  progress_cb=lambda value: (
      jobs.raise_if_cancelled(job_id),
      jobs.set_progress(job_id, value),
  ),
  ```
- **Исправление:**
  ```python
  def _on_remote_progress(value: float) -> None:
      jobs.raise_if_cancelled(job_id)
      jobs.set_progress(job_id, value)
  ...
  progress_cb=_on_remote_progress,
  ```
- **Объяснение:** явная функция выражает последовательность и соответствует сигнатуре.

### BUG-06. fmtBytes не умеет гигабайты: 2-гигабайтный файл показывается как «2048 MB»

- **Файл:** `frontend/src/main.tsx:469-471`
- **Суть:** после подъёма лимита до 2 GB все размеры ≥1 GB отображаются в MB.
- **Последствие:** нечитаемые значения в UI очереди загрузки и валидации.
- **Текущий код:**
  ```ts
  if (value < 1024 * 1024) return `${Math.round(value / 1024)} KB`;
  return `${(value / (1024 * 1024)).toFixed(value < 10 * 1024 * 1024 ? 1 : 0)} MB`;
  ```
- **Исправление:** добавить ступень GB:
  ```ts
  if (value < 1024 * 1024) return `${Math.round(value / 1024)} KB`;
  if (value < 1024 ** 3) return `${(value / (1024 * 1024)).toFixed(value < 10 * 1024 * 1024 ? 1 : 0)} MB`;
  return `${(value / 1024 ** 3).toFixed(value < 10 * 1024 ** 3 ? 1 : 0)} GB`;
  ```
- **Объяснение:** прямой функциональный пробел, актуализированный BUG-03/лимитом 2 GB.

## P2 — Отклонения от SSOT

### BUG-07. Дублированная логика нормализации чисел слов: countWords/normalizeWords

- **Файл:** `frontend/src/main.tsx` (composeCanonicalLiveSourceText, ~7136-7140) и рядом в adoption-утилитах
- **Суть:** нормализация слов (`toLowerCase + strip пунктуации + split`) реализована более чем в одном месте модуля 12k строк.
- **Последствие:** изменение правил токенизации в одном месте тихо расходится со вторым — сравнения overlap начнут врать.
- **Исправление:** вынести `normalizeWords/normalizeComparable/countWords` в `src/text-match.ts` (рядом с уже извлечёнными shortcut-display/recordings-list-reconciler), импортировать в обе точки.
- **Объяснение:** тот же паттерн SSOT-extraction, что уже применён для хоткей-отображения и реконсилера.

### BUG-08. Статический `<select id="model">` в index.html — cold-boot источник, рассинхронизирующийся с бэком

- **Файл:** `frontend/index.html:305-311`
- **Суть:** статические options tiny/base/small/medium/large-v3 существуют до гидратации; если бэкенд сконфигурирован иначе, первая отрисовка показывает неверный список (комментарий в коде признаёт проблему для remote-select, local оставлен как был).
- **Последствие:** мигание неверного выбора; выбор пользователя может быть временно невалиден.
- **Исправление:** привести к тому же паттерну, что remoteModelSelect — пустой select + build-time fallback через `__SHORTCUT_DEFAULTS__`-подобный инжект, либо оставить, но добавить комментарий-SSOT-ссылку. Минимально: синхронизировать статический список с `model_catalog.local.live_preview_models` на момент сборки невозможно (runtime-значение) → пустой select + skeleton-класс.
- **Объяснение:** устраняет второй источник списка моделей.

## P3 — UX / UI / Мелочи

### BUG-09. Сообщение валидации размера в мегабайтах при гигабайтных файлах

- **Файл:** `frontend/src/main.tsx:10655-10657`
- **Суть:** `File too large (1990 MB > 2048 MB cap)` вместо человеко-читаемых единиц.
- **Исправление:** использовать `fmtBytes` (после BUG-06) в шаблоне сообщения.

### BUG-10. 71 пустой `catch {}` в frontend/desktop

- **Файлы:** `frontend/src/main.tsx`, `desktop/main.js`
- **Суть:** большинство — осознанные non-fatal (рядом комментарии), но единая политика не зафиксирована; часть глотает ошибки в UI-экшенах без debug-лога.
- **Исправление:** политика «каждый пустой catch обязан иметь комментарий-причину» + точечное добавление `console.debug` в обработчиках пользовательских действий. Полный проход — отдельной задачей (риск трогать 71 место вслепую).

### BUG-11. `_fsync_file` открывает fd только для чтения

- **Файл:** `backend/storage.py:87-89`
- **Суть:** `open(path, "rb")` + `os.fsync` — POSIX-легально, но опирается на поведение «fsync флашит inode независимо от режима»; на экзотических ФС/платформах может дать EBADF.
- **Текущий код:**
  ```python
  def _fsync_file(path: Path) -> None:
      with open(path, "rb") as f:
          os.fsync(f.fileno())
  ```
- **Исправление:** `"rb"` → `"r+b"` (tmp-файл наш, права есть):
  ```python
  def _fsync_file(path: Path) -> None:
      with open(path, "r+b") as f:
          os.fsync(f.fileno())
  ```

### BUG-12. Легаси-ключи localStorage чистятся, но версия схемы не поднимается автоматически

- **Файл:** `frontend/src/main.tsx:603-607` (`LEGACY_LIVE_DRAFT_STORAGE_KEY` v1)
- **Суть:** миграционная механика завязана на ручное переименование констант; нового поля версии внутри payload нет.
- **Последствие:** будущая несовместимая схема потребует ещё одного легаси-ключа вручную; легко забыть.
- **Исправление:** добавить `schema: 2` внутрь PersistedLiveDraft и ветку миграции по числу (обратно совместимо).

### BUG-13. `terminal_observed_at` стартует по первому опросу любого клиента

- **Файл:** `backend/jobs.py:73-78`
- **Суть:** если статус однажды спросил посторонний запрос (например, health-check прокси), 15-минутный grace стартует, хотя настоящий клиент ещё не забрал результат.
- **Последствие:** теоретическая потеря результата при мягкой обрезке store.
- **Исправление:** считать observed только для GET конкретного job'а тем же origin/сессией либо увеличить grace; минимально — задокументировать инвариант в докстринге get().

### BUG-14. Двойной расчёт `recordingDomKey` на каждый reconcile

- **Файл:** `frontend/src/main.tsx:5895-5901` (map в renderRecordingsList)
- **Суть:** `filteredItems.map((it) => ({key: recordingDomKey(it), ...}))` плюс внутренние вызовы `recordingItemKey` в build/update — ключ считается 2-3 раза на элемент на каждый refresh (сотни элементов × частые фоновые обновления).
- **Последствие:** микрозатраты CPU на горячем пути UI; заметно только на 500+ записях.
- **Исправление:** мемоизировать ключ на объекте item (WeakMap) или передавать уже посчитанный key в update-callback (API реконсилера уже получает T с key).

### BUG-15. `syncRecordingsSearchControls` вызывается даже когда список скрыт

- **Файл:** `frontend/src/main.tsx:5916`
- **Суть:** DOM-запросы/aria-обновления на каждом refresh вне зависимости от видимости панели истории.
- **Исправление:** early-return по `hidden` родительской view.

### BUG-16. README не упоминает политику retention аудио

- **Файл:** `README.md` / `README.en.md`
- **Суть:** деструктивное по умолчанию поведение (BUG-02) нигде не задокументировано для пользователей.
- **Исправление:** абзац «Storage & privacy» с явным описанием и указанием, где лежат архивы.

### BUG-17. `desktop/packaging.test.js` покрывает только main.js/preload.js entrypoints

- **Файл:** `desktop/packaging.test.js:23-24`
- **Суть:** afterPack.js/unlockDist.js не требуют упаковки (это build-хуки), но если завтра появится require("./helper") в preload-цепочке модулей вне entrypoints, спека не увидит.
- **Исправление:** рекурсивный обход локальных require от обоих entrypoints (граф), а не только верхний уровень.

### BUG-18. `.nvmrc` (22.12.0) ≠ engines floor в frontend (`>=22.12.0`) — согласовано, но CI ставит Node 22.x latest

- **Файл:** `.github/workflows/tests.yml`
- **Суть:** `node-version: "22"` резолвит последний 22.x; расхождение с .nvmrc 22.12.0 может дать зелёный CI на новой Node при красном у пользователя на 22.12.
- **Исправление:** `node-version-file: .nvmrc` во всех трёх jobs (как это делает PR#1 — тут он прав по существу).

### BUG-19. `test_live_coverage_policy` требует tsc из node_modules — на чистой машине 10 тестов молча скипаются

- **Файл:** `backend/tests/test_live_coverage_policy.py:126-128`
- **Суть:** SkipTest честный, но разработчик без npm install увидит «203 passed» вместо фактических 193+skip и не заметит.
- **Исправление:** печатать явное предупреждение в stderr при скипе всей группы (SkipTest message уже есть; добавить summary-строку в конце прогона — unittest делает это сам, но причина тонет в verbose). Минимально: оставить, но задокументировать в CONTRIBUTING требование `npm --prefix frontend ci` перед прогоном бэкенд-тестов.
